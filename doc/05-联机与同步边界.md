# 05 · 联机与同步边界

> 版本：v0.1（草稿） · 2026-10-15
> 前置文档：01-项目定位.md（D8）、02-核心玩法与单局流程.md、03-塔、弟子与武学规则.md、04-局间奖励与存档规则.md
> 同步总规范以《太阳编辑器塔防AI协作开发指南》§5 为准，本文只做本游戏的具体映射与多人规则

## 一、定位（D8）

- 支持 1~4 人；**单人体验为设计基线**，双人次之，四人必须可用；
- 人数只改变规模，不改变玩法结构：任何人数下都是完整同一套游戏。

## 二、多人规则（04 文档第五节的正式化）

| 项 | 规则 |
|----|------|
| 分路 | 地图 4 路设计，玩家人数 = 启用的路数；每人一路，各自刷怪口、各自终点、各自基地生命 |
| 金币 | 独立，不可交易（防工作室/防破坏经济，旧图同规） |
| 基地生命 | 独立；一名玩家失败不判负他人，失败者可旁观或退出，按个人波次结算奖励 |
| 敌人强度 | 按「难度档 × 各自波次」独立计算，人数不影响单人强度（无组队血量膨胀惩罚） |
| 武学互赠 | 每人每局限赠 1 张、限收 1 张，受赠方须满足装配资格（04 已定） |
| 玩家离开 | 其路口停止刷怪、已生成敌人原地清除；其余玩家继续；存档按离开时已达成结算 |
| 房主离开 | 地图内按普通玩家离开处理（不判负他人）；房间存续由 KK 平台机制负责，本地不做额外处理 |

## 三、联机专属内容（多人的「为什么值得组队」）

| 内容 | 说明 |
|------|------|
| 联机专属渊源 | 佛光剑影、以柔克刚、百派来朝等（03 文档第五节）；跨路即可触发，不要求同路 |
| 武学互赠 | 送卡救急是联机核心爽点：「我出了张神卡救你一路」 |
| 全房奇遇 | 联机限定的全场级事件，设计为**需要多路同时响应的时序配合**（如「魔教两路同袭：两路须在同一波内各自击退来犯者，全房得共享奖励」）——多开可以静态凑组合，应付不来时序配合 |
| 组队名望加成 | 通关奖励 +10%/名队友，上限 +30%（04 已定）；**存活校验**：队友须存活至该玩家通关波次之后才计加成 |

## 四、同步边界映射（指南 §5 的本游戏清单）

**必须同步**（所有客户端同序执行）：

- 建造、进阶、出售弟子（含扣费与退款）；
- 波次推进：开始、生成、清场、首领出现与击杀、漏怪与基地生命；
- 三选一展示与选取、武学装配/卸下/升层；
- 奇遇触发与选择、挑战类奇遇的奖励；
- 武学互赠；
- 镇派弟子大招释放（影响全屏状态）；
- 敌人创建/移除/属性变更、镇山弟子阻挡与重生；
- 局末名望结算（先在同步状态算权威值，再写入存档）。

**仅本地**（`GetLocalPlayer` 分支）：Frame 面板、飘字密度设置、镜头音效、皮肤显示。

**网关**：所有 UI 操作只发「操作名 + 最少参数」短命令，由同步处理器取 `triggerPlayer` 重新校验资格（金币、阶段、占地、冷却），不信任载荷中的玩家编号（指南 §5.2）。

**随机数**：三选一、奇遇、敌人词缀等影响玩法的随机全部在同步逻辑消耗；同一次结果的共享随机只取一次；调试支持固定种子（指南 §5.3）。

## 五、建造者定位（定 01 遗留问题 3）

**建议定为「纯建造工具」，不做任何战斗职能（D17）**：

| 项 | 规则 |
|----|------|
| 形态 | 保留建造者单位（武侠题材里「掌门执事」 walks 到格子旁开建，符合题材、老玩家熟悉） |
| 战斗 | 无攻击力、不可被攻击、无技能、不占人口、不死亡 |
| 职能 | 建造入口：走到目标格 → 打开建造面板（Frame）；出售/进阶也在面板操作 |
| 未来扩展 | 若需要「掌门下场」，以后以镇派弟子为英雄位承载（D12），建造者永远不战斗 |

> 备选：无单位纯 UI 点格建造。更简洁但丢失题材手感，不采纳。

## 六、掉线与重连

War3 本体无重连能力，KK 平台的掉线保护以平台机制为准，地图内规则：掉线即按「玩家离开」处理（停刷、清怪、可继续）；如平台支持重连回房，重连后恢复旁观/继续资格。真实行为列入 KK 复验清单（04 文档 4.3）。

## 七、多开与刷分威胁模型（2026-10-15 补，回应独立评审 P0-2）

KK 平台的多开/小号生态是公开事实，联机专属设计必须按「多开者会尝试无成本复现」为前提：

| 威胁 | 现有防线 | 状态 |
|------|----------|------|
| 双开静态凑跨门派渊源 | 无（双开天然满足） | **接受**：静态组合的爽点多开者可得，但不构成对免费单人的不公平（无独占数值） |
| 多开挂机白拿组队名望加成 | 存活校验：队友须存活至该玩家通关波次之后 | ✅ 已堵 |
| 多开刷武学互赠 | 每人每局限赠/限收 1 张 | ✅ 已堵（收益有界） |
| 多开挂机刷名望 | 名望按个人波次结算，失败局收益低；组队加成已需存活 | ✅ 已堵 |
| 全房奇遇被多开低成本完成 | 时序配合设计：需多路在同一波内各自达成条件 | ✅ 设计上提高多开操作成本 |
| 房主离开/刷房 | 地图内按普通离开处理；存档按已达成结算 | 列入 KK 复验 |

原则：防线优先用**机制**（存活校验、时序配合）而非**检测**（平台不提供的机器识别不做承诺）。

## 八、待讨论

1. 全房奇遇的触发频率（建议：联机时每 3~4 波一次，与 02 文档 2.3 的个人奇遇并行）；
2. 是否需要「救援」机制：队友漏怪过多时他人可花资源支援（如帮建一座临时塔）——有 griefing 风险，倾向不做；
3. 2 人局共用一路的合作模式（两人同守一路、经济各半）——作为后续可选模式，MVP 不做。
